# Glosario — Semana 04

| Término | Definición |
|---|---|
| **Actor** | Quien usa el sistema desde fuera: una persona con un papel (bibliotecario) u otro sistema |
| **Análisis** | Actividad que responde qué problema se resuelve y qué debe hacer el sistema, antes de decidir cómo |
| **Arrays paralelos** | Varios arrays en los que la misma posición habla de la misma cosa: `codes[i]`, `titles[i]`. Señal de un objeto que aún no existe |
| **`as(...)`** | Método de AssertJ que añade una descripción al mensaje de fallo: `assertThat(x).as("CA-02").isTrue()` |
| **Caso de uso** | Descripción paso a paso de cómo un actor consigue un objetivo con el sistema, incluidos los caminos en que algo sale mal |
| **Colaborador** | En una tarjeta CRC, otra clase a la que esta necesita pedir algo |
| **Criterio de aceptación** | Ejemplo concreto, con datos, de cómo debe comportarse el sistema para dar una historia por terminada |
| **Dado, Cuando, Entonces** | Forma de escribir un criterio: estado de partida, acción y resultado. En inglés, *Given, When, Then* |
| **`@DisplayName`** | Anotación de JUnit que da a un test un nombre legible, con espacios y acentos, para el editor |
| **Dominio** | La parte del mundo de la que trata el sistema: una biblioteca, con sus libros, socios y préstamos |
| **Enunciado** | Texto corto que cuenta el problema con las palabras del cliente; el punto de partida del análisis |
| **Flujo alternativo** | Camino de un caso de uso cuando un paso no va bien; se numera con el paso y una letra (3a) y dice cómo termina |
| **Flujo principal** | Los pasos numerados de un caso de uso cuando todo va bien |
| **Glosario del dominio** | Lista de los términos del dominio, su significado para el cliente y su nombre en el código |
| **Historia de usuario** | Frase con la forma "Como... quiero... para..." que dice quién quiere algo, qué y para qué |
| **Objeto del dominio** | Cosa del dominio que el sistema recuerda y sobre la que actúa; en la semana 05 será una clase |
| **Postcondición** | Lo que es cierto al terminar el flujo principal de un caso de uso |
| **Precondición** | Lo que debe ser cierto antes de empezar un caso de uso |
| **Regla de negocio** | Decisión del cliente que el sistema aplica y que puede cambiar: plazos, tarifas, topes |
| **Requisito funcional** | Algo que el sistema debe hacer: "El sistema debe permitir buscar libros por título" |
| **Requisito no funcional** | Cómo de bien lo hace o con qué límites: rendimiento, plataforma, formato, seguridad |
| **Responsabilidad** | En una tarjeta CRC, algo que la clase sabe o hace |
| **Tarjeta CRC** | Ficha con el nombre de una clase, sus responsabilidades y sus colaboradores |
| **Trazabilidad** | Poder seguir un requisito hasta el caso de uso, el criterio y el test que lo comprueban, gracias a sus identificadores |
